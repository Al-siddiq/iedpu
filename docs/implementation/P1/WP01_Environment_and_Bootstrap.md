# P1-WP01 — Environment and Application Bootstrap

**Project:** IEDPU North Zone Digital Portal  
**Status:** Implementation branch prepared; local dependency resolution and XAMPP verification pending  
**Target branch:** feature/p1-wp01-environment-bootstrap  
**Approved baseline:** P1 Strategic Implementation Plan v1.0; SRS §2.1; P0 Engineering Decision Register v1.1

## 1. Objective

Establish reproducible local, staging and production application environments; align Composer requirements with the approved CodeIgniter and Shield versions; and provide a repeatable bootstrap procedure. No business modules, member data or production deployment are introduced in WP01.

## 2. Approved package baseline

| CodeIgniter 4 | 4.7.6 | Exact project baseline |
| CodeIgniter Shield | 1.4.1 | Exact authentication foundation |
| CodeIgniter Settings | ^2.1 | Shield transitive dependency; exact resolved version belongs in lockfile |

The repository lockfile at the start of WP01 contains CodeIgniter 4.7.4 and does not contain Shield. It must be regenerated by Composer on a network-enabled PHP environment. It is deliberately not hand-edited.

## 3. Environment profiles

Three templates are committed:

- .env.development.example — local XAMPP/PHP development.
- .env.staging.example — staging, using CI4 production boot mode (debug output disabled).
- .env.production.example — production, using CI4 production boot mode.

Copy exactly one template to .env on the relevant machine. Edit all connection values and secrets locally. Never commit .env, passwords, database dumps, private keys or live member data.

The application config reads the base URL, timezone, HTTPS setting and database connection from environment variables. Database debug is disabled when CI_ENVIRONMENT=production.

## 4. Local XAMPP setup

1. Keep the existing XAMPP PHP 8.2.4 installation for WP01 local development. No XAMPP/PHP upgrade is required for this local bootstrap.
2. Enable intl, mbstring, mysqli, openssl and fileinfo in the active PHP CLI and Apache PHP configuration. Enable curl where available.
3. Install Composer 2.x and point its Windows installer to the same XAMPP PHP executable used by the project.
4. Open PowerShell at the repository root.
5. Run Copy-Item .env.development.example .env if .env does not exist.
6. Create an empty local database named iedpu_dev using utf8mb4 and utf8mb4_unicode_ci. Do not import member data.
7. Confirm the database username/password in the local .env.
8. Run powershell -ExecutionPolicy Bypass -File scripts/bootstrap-windows.ps1.
9. If PHP is not on PATH, pass its executable explicitly: powershell -ExecutionPolicy Bypass -File scripts/bootstrap-windows.ps1 -PhpPath C:\xampp\php\php.exe.
10. Inspect the generated composer.lock and git status. Commit the lockfile; do not commit vendor/ or .env.
11. Start the local application with php spark serve --host 127.0.0.1 --port 8080 and open the configured base URL.

Generate a local encryption key with:

    php -r "echo 'hex2bin:' . bin2hex(random_bytes(32)), PHP_EOL;"

Store the generated hex2bin-prefixed value only in the local .env as encryption.key. Never paste it into GitHub or chat.

## 5. Dependency resolution

The manifest pins CodeIgniter 4.7.6 and Shield 1.4.1. Shield 1.4.1 requires codeigniter4/settings ^2.1. Composer must resolve and lock the compatible Settings release and all transitive dependencies.

The repository's existing composer.lock predates these requirements. Do not run composer install against that stale lockfile and do not manually manufacture lock metadata. Run the supplied bootstrap script on the actual development machine; it performs:

- PHP preflight;
- Composer manifest validation;
- composer update --with-all-dependencies --no-interaction --no-scripts (do not run composer install against the stale lockfile);
- manifest/lock validation;
- composer check-platform-reqs;
- full environment check;
- php spark --version;
- php spark routes.

The bootstrap uses --no-scripts because Shield's post-update hook only installs an optional development pre-commit hook; no runtime setup is skipped. The database checker boots CI4 in CLI mode and executes only SELECT 1. The generated lockfile must be committed. The vendor/ directory remains ignored.

## 6. Web-root and secret protection

Apache/shared-hosting document root must point to the repository's public/ directory only. Do not point the web root at the repository root. The app/, vendor/, writable/, docs/, .env and Composer files must not be publicly addressable.

Local development may use php spark serve. Staging and production must use HTTPS, a private writable directory, separate database credentials and a least-privilege database user. Production credentials must not be reused in staging or development.

Staging uses CI_ENVIRONMENT=production so exception details and debug tooling are not exposed. The profile remains separate from production through its own base URL, database and secrets.

Those belong to later P1 work packages or P2 onward.

## 10. Approved PHP 8.2.4 local compatibility decision (21 November 2026)

The user's WP01 preflight showed PHP 8.2.4 and all five required PHP extensions passing; only the original 8.4 minimum failed. The user's subsequent `composer install` was correctly rejected because `composer.lock` still specified CI4 4.7.4 and did not contain Shield. These are two different issues. The approved remedy is to lower the **local development** project minimum to PHP 8.2.4 and then run the WP01 Composer **update** process, which will resolve CI4 4.7.6, Shield 1.4.1, Settings ^2.1 and their dependencies.

This change updates `composer.json`, `public/index.php`, `spark`, the preflight checker, README and the SRS. CodeIgniter 4.7.6 and Shield 1.4.1 upstream manifests both require PHP ^8.2, so this version combination is supported at the declared package-constraint level. Actual installation is still subject to Composer platform resolution. The PHP 8.2.4 patch release is outdated: no public deployment or real member data is approved on this local runtime. Before staging/production, use a currently supported, security-patched PHP runtime and repeat the manual compatibility checks.

**Run after pulling the latest branch:** `powershell -ExecutionPolicy Bypass -File scripts/bootstrap-windows.ps1 -PhpPath C:\xampp\php\php.exe`. Do not commit the stale lockfile.
